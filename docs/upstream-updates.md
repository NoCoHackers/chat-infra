# Upstream update PRs

The workflow runs Mondays at 09:00 UTC and can be dispatched manually on `main`. Enable **Settings → Actions → General → Allow GitHub Actions to create and approve pull requests** where organization policy allows it. If that policy blocks PR creation, the workflow leaves the update branch in place and provides a manual PR link and update details in its job summary; no PR is opened automatically. On repositories where built-in-token PRs do not automatically run required checks (or require approval), approve the pending run or open an equivalent human-authored PR; the updater runs static validation itself but does not substitute for required checks.

The workflow proposes MDAD's default-branch commit, the latest stable OOYE tag and commit, and the latest patch/minor release on Node 22. After review and merge, dispatch **Deploy Matrix** on `main`; it requires a working offsite backup and GLaDOS start notice before applying the pins. The OOYE upgrade stages the pinned checkout and dependencies before stopping the service, and leaves its SQLite database and registration in place. If versions already match, it skips the bridge upgrade. The workflow assumes an already-bootstrapped droplet with the backup, notifier, and bridge services configured. Review the MDAD comparison for bundled image changes, upstream migration notes, and Element icon paths. PostgreSQL is constrained to major 18 in inventory; major upgrades are separate migrations. A failure is not automatically rolled back. For OOYE recovery, identify the previous checkout with Git reflog, locate the retained runtime/dependencies under `/var/lib/.noco-ooye-previous.*`, and use the pre-deploy offsite backup if the database format changed. Remove retained files only after the upgrade has been verified. Merge only reviewed pins; merging never deploys. Before a manual rollout, verify a fresh backup; afterwards check both Matrix and Discord message directions and Element branding.

Run `python3 scripts/check-upstream.py` from the repo to preview without changing pins. Do not reopen a closed proposal for the same exact diff automatically.
